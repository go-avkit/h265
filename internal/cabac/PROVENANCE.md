# Provenance of internal/cabac

Clean room. This package was written from ITU-T H.265 (V11) (01/2026) alone.
No other HEVC decoder (FFmpeg `hevc*`, libde265, HM, x265, gen2brain/h265, ...)
was opened for it, and none of the document's text is copied: clauses, tables
and equations are cited by number.

## Normative values, transcribed

| Where | What | Source in the document |
| --- | --- | --- |
| `tables.go` `rangeTabLps` | rangeTabLps[ pStateIdx ][ qRangeIdx ] | Table 9-52 (printed page 237) |
| `tables.go` `transIdxLps`, `transIdxMps` | state transitions | Table 9-53 (page 238), equation 9-66 |
| `contexts.go` `elements[].init` | initValue per ctxIdx | Tables 9-5 to 9-42 (pages 209 to 216) |
| `contexts.go` `elements[].spans` | which ctxIdx of which table belongs to which syntax element, per initType | Table 9-4 (pages 207, 208) |

The values were typed by hand from the page layout. Nothing is derived from
another implementation.

## Two readings

`spec_reading_test.go` is a second reading of every one of those numbers
(except Table 9-4, which `contexts_test.go` reads again by hand in the shape the
document prints it). It is generated by `testdata/specreading`, a parser of the
text layer as `pdftotext -raw` prints it, which shares nothing with the hand
transcription but the document. The tests fail on any disagreement, and check
what the tables must satisfy regardless of reading: the ctxIdx of a table's rows
tile it exactly, a table has as many values as its last ctxIdx says, rangeTabLps
falls with the state and rises with the range quarter, state 63 is 2 everywhere,
transIdxMps is `min(s+1, 62)`, an MPS renormalises at most one bit.

## Oracles

* `ref_test.go`: a bin-serial transcription of 9.3.4.3 (one `read_bits( 1 )` per
  shift, plain integers), using the second reading of the tables. The engine
  must equal it on every bin, every context variable, ivlCurrRange, ivlOffset
  and the bit pointer, after every operation: random streams, all 510 initial
  offsets, every ivlCurrRange with every bypass run length 0 to 32, adversarial
  streams, data cut short.
* the informative encoder of 9.3.5 (Figures 9-10 to 9-15), written from the
  flowcharts: streams it writes decode to the bins that went in, and after the
  terminating bin the bit pointer is exactly the number of bits written.
* the binarisations of 9.3.3.2 to 9.3.3.4, 9.3.3.10 and 9.3.3.11: the encoder
  side written from equations 9-13 and 9-16 and the clause, bin strings worked
  out by hand, and a forward bin-serial reading of random data.

## Mutations that must fail

Each was made, run, and reverted; each fails by assertion (engine vs reference,
or typed table vs parsed table), not by a crash:

1. renormalisation shift off by one (`- 23` to `- 22`);
2. renormalisation threshold `rng < 256` to `rng < 255`, in the LPS and MPS
   paths;
3. one entry of rangeTabLps changed by one (Table 9-52, state 10, quarter 2);
4. the bypass-run division done in 32 bits one bin too long (`k <= 24`);
5. the bypass-run remainder computed with the wrong divisor (`rng-1`);
6. the single-bypass mask inverted;
7. DecodeTerminate's comparison `>=` to `>`.

## Speed

The benchmarks (`bench_test.go`) compare the engine with this package's own
bit-serial reference only. They are not a performance claim against any other
decoder; that comparison (FFmpeg, libde265) comes with the slice-data PR.

## Scope and open points

* `cabac_bypass_alignment_enabled_flag` (9.3.4.3.6, ivlCurrRange set to 256) is
  refused: `Start` returns `ErrBypassAlignment` when told the flag is set
  (ParseSPS does not yet read sps_range_extension; go-avkit/h265#32). It changes ivlCurrRange without touching ivlOffset, and
  whether ivlOffset then stays below it is a property of the encoder that the
  one-division bypass run would have to be told about. It belongs to the high
  throughput profiles, outside the design's target.
* A stream whose first nine bits are 510 or 511 is refused (9.3.2.6 forbids
  it); everything after follows from that.
* Data that ends early reads as zero bits, and `Overrun` says so.
